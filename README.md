# 安吾アトラス(ango-atlas)

**本番: https://ango-atlas.vercel.app**(年表・作品一覧 / 文体マップ / 主題マップ / 一節から探す / リーダー)

青空文庫収録の坂口安吾コーパスを、**文体・主題・時系列・言及**の四軸で俯瞰する静的 Web アプリ。
クラスタや統計そのものではなく「同クラスタ内の近傍作品」「クラスタ境界の作品」、そして
**任意の一節から他作品の一節へ渡り歩く**経路を見せることで、読書案内として機能させる。

6 ビュー構成: 年表・作品一覧 / 文体マップ / 主題マップ / 一節から探す / 転換点 / リーダー。
作品 ID とチャンク ID を共通キーとして相互リンクする。詳細は [SPEC.md](SPEC.md)、
構想の背景と設計判断は [docs/CONCEPT.md](docs/CONCEPT.md)。

## L2 の実測(2026-08-25)

- **二重版ペア 50 組**・同一表記の重複 2 組を確定。照合は本文から漢字だけを残した骨格の
  4-gram Jaccard。分布は完全に二峰で、一致群の最小 **0.7597** に対し非一致群の最大 **0.0112**、
  32,352 組の比較でその間に 1 組も無い
- **題名一致では 14 組を取りこぼす**(「石の思ひ」⇔「石の思い」、「をみな」⇔「おみな」、
  「歴史と現実」⇔「歴史と事実」等)。逆に同題名の大半は連作で誤検出になる
- 仮名遣いを畳むと二重版の本文一致率は中央値 **0.9488 → 0.9964**(≥0.99 が 0/50 → 41/50)。
  規則は記憶からではなく 50 組の差分の実測から導出した(`docs/kana_fold_calibration.md`)
- ジャンル: 随筆・評論 267 / 小説 165 / 探偵小説 21 / 巷談・ルポ 20 / 紀行・日記 15 / 不明 25。
  初出年 1927–1955(不明 15)
- 初出年は 2 出所(カード欄・本文フッタ)から取り、1 件の食い違い(card45737)は元号と整合する
  側を採った — 青空文庫側の西暦誤植を検出したことになる


## L3 の実測(2026-08-25)

- **O-1 が通った**: 二重版 50 組**すべて**で相手が最近傍(最悪順位 1)、
  k=3..10 のすべてで同一クラスタ。特徴量が仮名遣いではなく文体を捉えている根拠になる
- ただし**畳むことが O-1 を救っているわけではない**。品詞を原文で取った対照条件でも同じ結果で、
  文長・句読点・文字種・会話文比率といった文字レベルの特徴が支配的だった。畳む効果は品詞
  ブロックに限られる(版間 L1 0.0218 → 0.0023、S/N 5.0 → 45.8)。埋め込みを扱う L4/L5 で測り直す
- **O-1 が実際に欠陥を捕まえた**: チャンク平均で末尾 9 字のかけらを等重みで混ぜていたため
  card45744 の平仮名率が 0.607 → 0.406 に歪み、最近傍順位が 81 位に落ちて発覚した。
  単体テストは全て緑のままだった
- ARI(ジャンル)は k=4 で最大 0.248、k=8 で 0.091。ARI(時期)は 0.002–0.110。
  低いこと自体は欠陥ではない — ジャンルと文体の食い違いを見せるのが目的で、
  近傍 6 作品のうち 4 作品以上が別ジャンルの作品が **66 件**ある
  (「青春論」は随筆・評論だが近傍 5/6 が小説、など)


## L4 の実測(2026-08-25)

- **採用: ruri-v3-30m / 原文入力 / 文脈前置きあり / 192 次元 float16(5.93 MB)**
- 表記への頑健性(二重版チャンク 1,026 組)は **R@1 = 1.000**。しかも**原文のまま**で、
  仮名遣いの正規化は不要だった。L3 で残した「fold の真価は L4 で問われる」への答えは
  「埋め込みには要らない」。`to_modern` は A で差が無く B ではむしろ下がった
- 意味検索(人手 35 問)は R@1 0.400 / R@10 0.571。e5-small は R@1 0.143 で明確に劣る。
  低さの原因を疑って文脈前置きの有無を同一部分集合で比べたが**ほぼ互角**で、
  交絡ではなく 30M モデルの限界だった。L5 の BM25 併用で補う
- 圧縮では**平均を引いてはならない**。中心化すると単位長ベクトルの内積が保たれず、
  全次元を残しても R@10 が 0.885 に留まる。中心化なしなら 256 次元で 1.000
- int8 は 2.96 MB まで落ちるが R@10 0.958 で、192 次元と 256 次元が同値になる
  (次元より量子化が効く)。品質差に見合わないので float16 を採る


## L5 の実測(2026-08-25)

- **目玉の「一節から探す」が動いた**。リーダーの段落末の ◦ を押すと、その一節を起点に
  他作品の近い一節が出る。クエリ時のモデル推論はゼロ — 事前計算した float16 ベクトルの
  内積だけ。1 問 **15.3 ms**(node 実測、15,430 本 × 176 次元)
- BM25 は名詞のみの索引(34,236 語・1.83 MB)。1 文字の漢字語を入れないと「桜」「雪」「碁」が
  引けないので入れた(postings は 508k → 672k)。問い側の分かち書きは配信語彙への最長一致で、
  形態素解析器をブラウザに持ち込まない
- **二実装照合が事故を捕まえた**。`bm25_terms.txt` を `write_text` で書いたため Windows で
  CRLF になり、JS の `split("
")` が全語に CR を残して検索が全滅した。Python 側は
  `read_text` の改行正規化で気づけない。JS と Python を突き合わせて初めて露見した
- 検索データは **7.49 MB**(N-04 の 8 MB 以内)。192 次元だと 7.98 MB で余裕 0.02 MB しか
  残らず次の変更で必ず割るため、**176 次元に落として 0.5 MB の余裕を買った**
  (R@10 0.9925 → 0.9815)
- 二重版・重複の **52 作品**を検索結果から除外(新字新仮名を残す)。リーダーでは両版とも読める


## L6 の実測(2026-08-25)

- **BERTopic は採らなかった**。このコーパスの埋め込み空間には密度の谷が無く、HDBSCAN は
  PCA 32 次元 × min_cluster_size 15〜60 のいずれもノイズ 71〜85%、低次元では巨大クラスタ
  2 個に潰れた。単一作家の散文は連続体である。**k-means + c-TF-IDF** に変えて全チャンクに
  主題を割り当てた(主題 20)
- 主題は読める形になった: 文学論と作家論 / 文明批評と戦争 / 将棋と碁の勝負師 /
  戦国の天下人 / 病・薬・医者 / 古代の権力と天皇 ほか。**1 作品に偏った主題は「作品固有」と
  明示**する(吹雪物語 99.5%、街はふるさと 98.7% — 長編がそのまま一つの塊になる)
- **転換点は 1931・1934・1937・1938・1944・1946**。うち 4 件が通説区分の近傍
  (1931 風博士 / 1937-38 吹雪物語 / 1946 堕落論)。1950 の巷談期は検出されなかった。
  **一致は主張しない** — 検出器は通説を知らないし、合致を要求するテストも書いていない
- 変化点検出の**罰則は合成データで較正**した。理論値(BIC)のままだと純雑音 200 本の
  **79% で変化点を「発見」**してしまう。採用値は誤検出 0% / 3σ の段差で検出力 100%
- 言及コミュニティ 59 群。大きいものは **牧野信一圏**(22 作・牧野/信一/中島健蔵/嘉村礒多)、
  **芥川/葛巻圏**(20 作)、**囲碁将棋圏**(18 作・木村/升田/本因坊/呉清源)、**戦国圏**(17 作)、
  **新潟圏**(12 作・新潟/信濃川/越後)。構想が予想した交友・関心圏が実測で出た

## 設計上の中心的判断

サーバー・API を持たない(N-01)ため、目玉機能の一節検索は**クエリ時にモデル推論を必要としない**
設計にした。段落クリックを起点にすれば、必要なのは事前計算済みベクトルの内積だけで済む。
自由語は BM25 の静的転置索引が担い、自由語の意味検索だけを遅延ロード・オプトインの追加機能
(F-25)として最後に置く。

## 検証オラクル

背骨は **O-1「二重版一致」**。青空文庫の安吾コーパスには同一作品の新字新仮名版と新字旧仮名版が
両方あるタイトルが存在し、これは「同じ文体・同じ内容で表記だけが異なる」ラベル無しの正解対である。
文体特徴量が表記を拾っていれば必ずクラスタが割れるため、前処理と特徴量の妥当性を自動検証できる。
ほかに往復検査(O-2)、既知近傍(O-3)、ARI(O-4)、量子化損失(O-5)。詳細は [TEST_SPEC.md](TEST_SPEC.md)。

## ループ計画

| ループ | 内容 | 要求 |
|---|---|---|
| L1 | 作家ページ実測・本文取得・パーサー・往復検査 ✅ | F-01..04 |
| L2 | メタデータ・二重版ペア表・仮名遣いの折りたたみ ✅ | F-05..07 |
| L3 | 文体特徴量 → クラスタ → 文体マップ + 年表 + リーダー ✅ | F-08..12 |
| L4 | チャンク分割・埋め込み 2 モデル比較・圧縮決定 ✅ | F-13..15 |
| L5 | 一節から探す + BM25 自由語検索 + 版重複排除 ✅ | F-16..18 |
| L6 | 主題マップ・転換点・言及グラフ ✅ | F-19..22 |
| L7 | 相互リンク統合・固定フッタ・app-menu 掲載・GitHub 公開 | F-23..25 |

L3 で一度出荷するのは安全側の切り方で、埋め込みが不発でも「文体マップ + リーダー」だけで
作品として成立させるため。
