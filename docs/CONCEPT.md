# 構想 — ango-atlas(安吾アトラス)

青空文庫収録の坂口安吾コーパスを、**文体・主題・時系列・言及**の四軸で俯瞰し、
「一節から一節へ渡り歩く」読書案内を与える静的 Web アプリ。

- 名称案: **安吾アトラス / `ango-atlas`**(別案: 堕落レンズ `daraku-lens`、ふるさとアトラス)
- カテゴリ: app-menu 📚 文学・翻訳(cat5)。kokoro-graph / kiko-atlas / jikenbo-atlas の姉妹
- 本番: `ango-atlas.vercel.app`(想定)

---

## 1. なぜ「一人の作家 × 全作品」がこの題材で効くか

- ジャンルが小説・評論・随筆・探偵小説・巷談と極端に多様で、**ジャンルラベルと文体クラスタが
  食い違う**現象そのものが読み物になる(「イノチガケ」「二流の人」が評論側に寄るか、
  「教祖の文学」が小説側に寄るか)
- 初出年がほぼ判明しているので、**文体の変化点検出**が意味を持つ(1931 風博士 / 1938-39 吹雪物語・
  紫大納言 / 1946 堕落論 / 1950- 巷談・捕物)。通説の時期区分と一致するかは検証可能な問い
- **新字新仮名版と新字旧仮名版が両方あるタイトルが数十件**存在する。これが天然の検証オラクルになる
  (詳細は §5)。フリートの流儀(オラクル先行)にそのまま乗る

## 2. Vercel 制約への設計上の答え

フリートの既定は「サーバー・API 不要の静的サイト(N-01)」。埋め込み検索はここと衝突しやすいので、
**クエリ時にモデルを必要としない機能を目玉に据える**のが本構想の核心。

| 機能 | クエリ時に必要なもの | 静的で成立するか |
|---|---|---|
| **一節から探す**(段落クリック → 近傍段落) | 事前計算済みベクトルの内積のみ | ✅ 完全に成立。**これを目玉にする** |
| 自由語検索(語句) | BM25 転置索引(静的 JSON) | ✅ 成立 |
| 固有名詞検索 | 同上 | ✅ 成立(埋め込みが弱い領域を BM25 が埋める) |
| 自由語の**意味**検索 | クエリ埋め込み | △ transformers.js で ruri-small を**遅延ロード・オプトイン**(初回数十 MB)。既定 OFF |
| cross-encoder リランク | 重い推論 | ✗ 出荷しない。オフライン評価でのみ使い、精度差を SPEC に記録 |

つまり L1〜L5 は 100% 静的。意味検索は「押したら読み込む」追加機能として最後のループに置く。
将来 Vercel Function + 埋め込み API に切り替える余地は残すが、既定経路にはしない。

### データ量の見積もりと圧縮(実測ゲート項目)

- 370 作 × 約 400 万字 → チャンク 1.0〜1.5 万件(300〜500 字、段落境界優先)
- 768 次元 float16 素のまま = 約 23 MB → **重すぎる**
- 対策: PCA 256 次元 + int8 量子化 → 約 3.8 MB。**近傍上位 50 件の順位が原次元とどれだけ一致するか**
  (Recall@10 / Kendall τ)を較正ループで実測し、次元と量子化を決める
- 表示用本文は作品単位シャードで遅延取得(リーダーを開いたときだけ)

## 3. 画面構成(6 ビュー・作品 ID と チャンク ID を共通キーに相互リンク)

1. **年表 / 作品一覧** — 初出年 × ジャンル × 文字数。全作品の入口。フィルタとソート
2. **文体マップ** — 文体特徴量 → 標準化 → PCA(UMAP は再現性の都合で従)→ 散布図。
   Ward 法デンドログラムを「読書パス候補」として併置。**ジャンルラベルと不一致の作品を強調表示**
3. **主題マップ** — チャンク単位 BERTopic のトピック × 初出年ヒートマップ(主題の推移)、
   トピック × ジャンルのクロス集計(**同じ主題の小説版・評論版のペア抽出**)
4. **一節から探す**(目玉) — リーダー上の段落をクリック → 他作品の近傍段落を並べる。
   作品あたり最大 2〜3 チャンクに抑えて多様性を確保。「文学のふるさと」の突き放しが
   「桜の森の満開の下」に再現される類の自己反復を可視化する
5. **転換点** — 隣接作品間の文体距離の時系列 + PELT 変化点。通説の時期区分を帯で重ねて照合
6. **リーダー** — 青空文庫記法パーサー(ルビ《》・｜・注記 [#…])。往復検査つき。全ビューの着地点

固定フッタ(kiko-atlas 準拠): © / GitHub / 歩き方 / 設計図 / App Menu。

## 4. パイプライン(Python・オフライン)

```
青空文庫 作家ページ実測(person ID は L1 で実測確定)
 → 全カード一覧 data/aozora_works.json(件数は定数で書かない = HC-016)
 → 本文取得(1 秒間隔・キャッシュ優先・取得元 URL と取得日を記録 = 実測主義)
 → パース(ルビ/注記/底本分離)→ 往復検査 100%
 → 正規化(旧仮名 → 新仮名。※ 変換は検証用に別系統として保持)
 → チャンク分割(段落優先・上限 500 字・作品名/ジャンル/初出年を先頭に付す contextual chunking)
 → ① 文体特徴量  ② TF-IDF/BERTopic  ③ 埋め込み(ruri / e5 の 2 系を較正で比較)
 → PCA + int8 量子化 → web/data/*.bin + *.json
```

固有名詞共起グラフ(Louvain)は ② と同じ形態素解析結果から派生させる。

## 5. 検証オラクル(このプロジェクトの背骨)

| ID | オラクル | ゲート |
|---|---|---|
| O-1 | **二重版一致**: 同一作品の新仮名版と旧仮名版が同じ文体クラスタに入るか | 一致率と ARI に閾値。割れたら「特徴量が表記を見ている」証拠 → 前処理をやり直す |
| O-2 | **往復検査**: パース → 再直列化が原文と完全一致 | 100%。1 件でも外れたら L1 完了不可 |
| O-3 | **既知近傍**: 「堕落論」核心段落を query に「続堕落論」「日本文化私観」「教祖の文学」が上位 | 手作りの評価セット 30〜50 問で Recall@10 を測り、モデル選定の根拠にする |
| O-4 | **クラスタ妥当性**: シルエット係数ではなくジャンル/時期ラベルとの ARI で解釈 | 数値は較正ループで実測してから閾値を決める(先に閾値を書かない) |
| O-5 | **量子化損失**: 圧縮ベクトルの近傍順位が原次元とどれだけ一致するか | §2 の圧縮方式決定の根拠 |

O-1 が特に強力で、「数十件のラベル無しペアが自動で正解を持っている」状態を作れる。

## 6. ループ計画

| ループ | 内容 | 主な成果物 |
|---|---|---|
| L1 | 作家ページ実測・本文取得・パーサー・往復検査 | `data/aozora_works.json`, `data/raw/`, パーサー + O-2 |
| L2 | メタデータ整備(ジャンル統制語彙・初出年・二重版ペア表)・前処理(旧仮名正規化) | `data/works_meta.json`, 二重版ペア表 = O-1 の素 |
| L3 | 文体特徴量 → クラスタ → **文体マップ + 年表 + リーダー** 公開 | 初回 Vercel デプロイ。ここで一度出荷する |
| L4 | チャンク分割 + 埋め込み 2 モデル比較(較正)+ 圧縮決定 | 評価セット 30〜50 問、O-3/O-5 の実測記録 |
| L5 | **一節から探す** + BM25 自由語検索 | 目玉機能。作品あたり件数制限で多様性確保 |
| L6 | BERTopic 主題マップ・転換点・言及グラフ | 残り 3 ビュー |
| L7 | 相互リンク統合・固定フッタ・app-menu 掲載・GitHub 公開・(任意)transformers.js 意味検索 | 完走 |

L3 で一度公開してしまうのが安全側。埋め込みが不発でも「文体マップ + リーダー」だけで作品として立つ。

## 7. 落とし穴(会話で挙がったもの + フリートの経験から)

- **旧仮名版の重複**: 索引に入れるのは片方のみ。検索結果に同一作品の別版が並ぶのを防ぐ
  (ただし O-1 の検証系には両方残す)
- **長編の希釈**: 作品ベクトルをチャンク平均で作ると個性が消える。作品は
  「トピック分布」で表現し、平均プーリングは使わない
- **短編と長編で分散が違う**: 一定長チャンクの分布として扱い、文字数で層別
- **クラスタそのものは見せない**: 読書案内として機能するのは「同クラスタ内の近傍」と
  「クラスタ境界の作品」。UI はそちらを主役にする
- **LLM 生成のトピック名**は本文と明確に区別して表示(生成物と実測を混ぜない)
- **UMAP は乱数依存**なので既定は PCA。UMAP を使うなら seed 固定と再現手順を SPEC に書く
- **作品数は実測で確定**(約 370 という数字は会話上の見積もり。カード一覧との集合一致で決める)

## 8. スコープ外

- 他作家への拡張、英訳・対訳
- 本文の校正・改変(取得したままを正とする)
- 学術的な文体論の主張(出すのは実測値と可視化まで。解釈は案内文の範囲に留める)
- ログイン・保存機能
